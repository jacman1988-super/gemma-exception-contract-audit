Auditing Import-Based Test Selection Around a Local Gemma 4 Repair Loop
Subtitle: A small executable study of uncertainty fallback and patch revision
Author: Jacek Adamek

FINAL LOCAL RESEARCH REPORT — unpublished, not submitted; participant review required.
This pilot does not yet establish a novel research contribution or competitive
performance. It is a candidate research direction, not a completed paper track entry.

ABSTRACT

Test selection may reduce execution work for local coding assistants while also
hiding regressions. We implement ImportGuard, an inspectable Python module-import
selector with explicit full-pool fallback for recognized uncertainty. Eight original
controlled cases expose two alias-related misses in an initial version. A correction
detects all eight faults using 33 test-module executions versus 48 for the full
constructed pool, but those cases informed the correction. We then reproduce two
public bug/fix pairs with upstream regression tests. The corrected fallback selector
detects both bugs but selects all five declared test modules, providing no selection
saving. Actual local Gemma 4 E2B inference proposes one unresolved and one passing
patch. On the unresolved case, one revision with test feedback and a separate
revision without feedback produce the same passing patch. These observations
motivate reporting negative results, global fallback cost and no-feedback controls.
A frozen expansion selects five cases from two new repositories: three reproduce in the primary environment, one becomes reproducible only after a separately recorded UTF-8 compatibility follow-up, and one remains uninformative. All three primary model proposals and the secondary proposal remain unresolved. These observations do not demonstrate a general agent improvement or a safe selection algorithm.

1. INTRODUCTION

Local coding assistants incur both inference and validation costs. Running fewer
tests can reduce validation work, but an irrelevant passing subset can conceal an
incorrect patch. A coarse import graph is attractive because it can be constructed
without executing a repository. Python's dynamic behavior makes its limitations
particularly important to expose.

Our question is narrow: what does an explicit uncertainty fallback buy, and when
does it erase the intended selection saving? A second question concerns revision:
when a model corrects a patch after seeing failed tests, would a further review
without those results also have corrected it?

The current work contributes original selector and experiment code, adversarial
fixtures, pinned upstream reproduction records and actual local model traces. Import
dependency analysis, conservative fallback, mutation experiments and test-guided
repair are established ideas. We do not claim their invention. A defensible novel
contribution requires further study beyond the present pilot.

2. RELATED WORK

Rothermel and Harrold's safe regression-test-selection work [1] uses control-flow
information and execution history, with a safety argument under stated assumptions.
ImportGuard's module-level AST graph has no comparable proof. Falling back for some
recognized dynamic constructs does not make it safe for arbitrary Python.

SWE-bench [2] evaluates real repository issues and generated changes through
execution. Our eight constructed cases and two convenience-selected public fixes
are far smaller and are not comparable benchmark results. We use the distinction to
avoid presenting local fixture success as evidence of general software-engineering
ability. A systematic review of contemporary selection and agent methods, including
stronger hybrid and coverage baselines, remains necessary.

3. IMPLEMENTATION AND PROTOCOL

ImportGuard reads Python source, parses ASTs and resolves static module imports,
including relative imports. Reverse reachability from changed production paths
selects affected test modules. Recognized uncertainty, parse failures, unknown or
non-Python changes, package initialization changes and empty static selections
trigger a full-pool fallback. Source hashes accompany the selection. The corrected
version tracks directly imported import_module aliases and assignment chains of
known dynamic-call names. It is deliberately conservative and not scope-sensitive.
Indirect runtime bindings, plugins, reflection and resource dependencies remain
limitations. The implementation does not execute the inspected source.

The no-fallback ablation uses the same import graph and keeps an empty selection
when appropriate. A clean-line-coverage baseline traces each constructed test before
mutation; it does not observe arbitrary resource reads. Random choices use seeds
0–19 and match the fallback method's selected-module count for each case. Identical
random subsets share a recorded execution, rather than being treated as independent
timing samples. Module count is not runtime or end-to-end compute cost.

The eight original cases cover direct, transitive and relative imports, direct
dynamic loading, two alias patterns, a non-Python resource change and package
initialization. Each has six test modules and a deliberate arithmetic fault. An
irrelevant test in the alias cases imports the changed module, so a nonempty static
selection cannot accidentally invoke the empty-selection fallback. Clean suites
must pass, and full faulty runs must fail the expected fee assertion rather than
an infrastructure error. We preserve the initial selector and all negative outcomes.

After inspecting these controlled cases and correcting alias handling, we freeze
the selector for a public-source pilot. The cases are boltons IndexedSet.update [3]
and more-itertools bucket validation [4]. Their BSD-3-Clause and MIT license texts,
parent/fixed commits, archive hashes and test-file hashes are included. Fixed-version
tests are held constant while only the changed production file is reverted to its
parent. Newly added upstream regression tests are thus present on both versions.
The selector receives the production path, not the regression-test change path.

The declared pool has three boltons modules and two more-itertools modules; these
are bounded subsets, not complete upstream suites. Selection scans the full source
tree, then intersects choices with the declared pool. Pytest 8.4.2 runs with automatic
external plugin loading disabled. No selector change follows the upstream outcomes.

The initial alias misses demonstrate that a useful-looking nonempty selection can
hide the relevant test. The corrected 8/8 is a regression result on inspected cases,
not a held-out estimate. Coverage misses the resource case because Python execution
coverage does not record arbitrary file dependencies. We do not infer superiority
over production tools that instrument resources or combine several dependency types.
The coverage setup cost is additional and absent from the module counts above.

In the public pilot, fixed references pass 74 boltons tests and 768 more-itertools
tests. Reverting production code yields four expected failures plus 70 passes and
one expected failure plus 767 passes, respectively. Both bugs are reproduced.

The fallback method provides no module-count saving here. Its global uncertainty
rule flags dynamic behavior in boltons production code, documentation and function
builder tests, and in more_itertools/more.py. Recognizing unrelated dynamic behavior
can erase the intended saving. Random selection at this full-pool budget is the
same full pool, not an informative independent baseline. The no-fallback success on
these two fixes does not overturn its controlled alias misses.

5. ACTUAL LOCAL MODEL AND REVISION PILOT

We run Google's official Gemma 4 E2B instruction-tuned QAT Q4_0 GGUF [5], revision
675cff42a74c774d6cb76f76d8eacb49b48c9b93, with llama.cpp build 11429 [6]. The
text-only local setup uses two CPU threads, a 2048-token context, a 192-token output
cap, temperature zero, seed 20261014 and reasoning off. Model and executable hashes,
exact prompts, raw outputs and process times are recorded. Downloaded weights and
runtime binaries are excluded from the deliverable. No paid inference is used.

Each initial prompt contains a public bug description and a short buggy function,
without the gold patch or fixed regression-test source. An assistant had already
inspected the fixes while constructing the prompts; researcher-choice bias is not
eliminated. Known public changes can also occur in model training data. We make no
contamination-free capability claim.

The initial boltons suggestion replaces chain(others) with list(chain(others)),
which still does not flatten input iterables. It also violates the requested
single-line edit format by returning a two-line block. Applied without repair after
inspection, it leaves four failures. The more-itertools suggestion selects the
default validator only when validator is None, and all 768 declared tests pass.
Successful subprocess exit alone is never counted as a correct patch.

On the failed boltons case, a protocol is saved before two additional generations.
Both start from the same previous model edit and permit one revision, with the same
model, seed, temperature and output cap. The no-feedback arm asks for a further
review. The feedback arm additionally supplies the first 2000 characters of the
actual failing test output. Input lengths differ, so input compute is not matched.

Both arms return the identical function using list(chain(*others)); both resolve
the declared regressions. Because the resulting sources are identical, one actual
74-test passing run is shared and explicitly marked as reused. The reference fix
uses a different expression; the model output is not replaced by it. The control
shows that this case cannot establish a benefit attributable to test feedback.
Generation process observations are about 19 and 41 seconds, respectively, not
repeated timing estimates. All proposed assignments are inspected before tests run;
generated commands are not executed. This is a bounded revision pilot with assistant
review gates, not a general autonomous coding-agent benchmark.

Initial restricted-process model launches timed out without output. Direct local
launches succeeded. Failed attempts are retained separately as execution failures,
not model-quality failures. A protocol audit also records a decoded-text versus
raw-file hash distinction and verifies that both actual snippets match UTF-8 source.

6. FROZEN EXPANSION TO NEW REPOSITORIES

After the initial pilots, we freeze the selector, case list and module pools before
observing outcomes for five changes from two previously unused repositories:
cachetools [7] and jmespath [8]. This is prospective relative to selector development,
but convenience-selected, not representative or randomized. Three cases share one
repository. Commit descriptions and dependencies were inspected before the freeze;
no test or model outcome determined inclusion. All selected cases are retained.

The primary Windows run reproduces three cachetools bugs. Fixed references pass
113, 100 and 88 tests; reverted production code yields one, four and one failures,
respectively. The jmespath float case fails collection because fixture data cannot
be read under the default encoding. The jmespath functions case passes nine tests
with one skip on both versions, so the declared tests do not reproduce that defect.
Neither case is silently removed or replaced.

All three cachetools changes are in a package initializer, so the frozen policy
falls back and runs all 12 declared modules across those cases. The no-fallback
ablation selects zero: this graph does not resolve the src package layout correctly.
That is a missed-fault limitation, not useful saving. No post-outcome correction is applied to that frozen assessment. A separate UTF-8 compatibility follow-up, after the primary encoding
failure, passes 952 float-case tests with one skip on fixed code, then yields four
failures and 948 passes on parent code. Both selector modes choose all three modules.
This secondary observation is distinct from the primary prospective assessment.

The same local E2B settings and one-generation limit produce three primary patch
proposals. After inspection, all fail the declared pools: empty-cache handling leaves
one failure; the growth edit increases failures from four to ten; expired-overwrite
handling leaves one failure. A separate generation on the secondary float case
returns identical old/new code. Its actual parent failure is reused and marked.
No proposal is repaired and no extra generation replaces an unsuccessful result.

Localization is oracle-assisted: old diff coordinates select buggy functions, and
public commit messages may explain the intended fix. Gold patch text and regression
test source are withheld. These tasks can be in training data. The separate primary
and compatibility-follow-up outcomes cannot be pooled into a population success
rate or an end-to-end agent claim. Protocols, licenses, source hashes, exact outputs
and failed references remain in the package. See expansion-study.txt for reproduction.

6.1. Separate post-outcome implementation correction

After recording the expansion, we create a separate development variant with
explicit repository-relative source roots. Declaring src removes that prefix
from module names while keeping repository-relative selection paths. Colliding
module names across roots trigger fallback. The original importguard.py and its
frozen assessment hash remain unchanged; no published comparison above is rescored.

Seven new tests cover source-layout behavior and retained uncertainty rules, in
addition to nine frozen-selector tests. On the three inspected cachetools cases,
the corrected static graph recovers all four declared modules per case and actual
test runs detect the known defects. Identical static/fallback choices share one
run. Initialization changes still trigger the full pool, so this is a regression
correction, not a test-saving or held-out quality result. The development variant
needs a separately declared new assessment before any general performance claim.

7. LIMITATIONS AND NEXT RESEARCH GATE

Eight purpose-built cases, two initial public fixes, five selected expansion cases
and a single revised case do not support population confidence intervals or general
success rates. The frozen expansion provides a limited repository-separated check;
its failed references and compatibility follow-up constrain interpretation. Initial pilot outcomes were inspected during development. The later frozen expansion
was not used to retune the selector, but must not now be reused as an untouched set.
We measure selected modules and bounded test outcomes, not complete upstream-suite
correctness, actual task solving across repositories or net agent acceleration.
Global uncertainty can over-trigger, while unrecognized dynamics can under-trigger.

The next study must freeze a larger, independently sampled and licensed task set,
split by repository, preregister total inference/test budgets and include coverage
setup cost. It should compare actual iterative agents and no-feedback revisions,
use stronger published baselines and report every infrastructure failure and timeout.
A novel contribution and contest competitiveness remain unestablished. Until those
steps are complete, the present work is an auditable pilot with useful negative
observations rather than a finished competition paper.

8. REPRODUCIBILITY AND AI DISCLOSURE

The package contains selector versions, original fixture generators, actual process
outputs, pinned upstream acquisition/reproduction scripts, exact model prompts,
reviewed patch evaluators, third-party notices and source manifests. Nine tests cover the frozen selector; seven additional tests cover the separate
development variant. Python's standard library suffices for the selector and synthetic cases;
the upstream pilot uses pytest 8.4.2. Raw records are authoritative over rounded
numbers in this draft. No competition submission or public repository was created.

Codex assisted research, implementation, experiments and drafting. The participant
must inspect, understand, reproduce and take responsibility for the work before any
publication. No unperformed experiment, author expertise or organizer endorsement is
claimed. The fixed upstream regressions are attributed third-party work.

FINAL FOLLOW-UP: DISCOVERY, NEW REPOSITORIES AND EXCEPTION CONTRACTS

A separate development selector supports explicit source roots and test-name
patterns. The original test_ prefix omitted suffix-named tests even during
fallback. Four intentionally constructed regression fixtures give 2/4 detections
before correction and 4/4 after correction; they do not estimate generalization.

Two additional repositories were selected before test outcomes. The ItsDangerous
Windows timestamp correction reproduces: its fixed timed module passes 101 tests,
while parent source fails one. After a separately recorded missing-freezegun
environment correction, the selector detects the fault using the entire declared
module. SortedContainers passes 59 tests in both versions and is retained as
uninformative. Neither case demonstrates module-selection savings.

Actual local E2B inference on the ItsDangerous snippet yields a truncated
256-token response, then an identical-prompt 1024-token proposal passing all
297 upstream tests. A post-outcome differential probe nevertheless detects
that the generated exception payload is a string rather than the original
bytes. A feedback-informed 512-token proposal, and a further explicitly localized
512-token proposal, edit the wrong handler and retain the original failure.
All outputs are preserved. Three additional diagnostic tests check payload,
valid roundtrip and direct-conversion exception behavior. The latest proposal
fails one, whereas the upstream reference passes all three. These are post-outcome
contract probes, not an independent test pool. No generated patch is silently
repaired or counted as successful because it only passes the upstream suite.

A separately labeled, manually reconstructed upstream-equivalent reference
correction provides a usable local repair and validates the diagnosis. It is
not a Gemma success, an original bug discovery or a new scientific contribution.
The complete package is an exploratory research record; further independent
assessment, stronger comparisons and a defensible contribution remain necessary
before treating it as a completed competition paper. New results do not reverse
the earlier negative findings or establish safe test selection.
