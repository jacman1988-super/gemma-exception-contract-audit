ImportGuard: uncertainty-aware regression-test selection for local coding agents
Working research plan, NOT a finished paper. 14 October 2026.

Abstract: We implement an inspectable Python import-graph selector with explicit
uncertainty fallback and a small executable diagnostic resource. Controlled fixtures
check behavior; they do not establish effectiveness on real software or Gemma agents.

Introduction: Local coding agents have limited inference and testing budgets. Test
selection can save work but can also hide regressions. We investigate whether exposing
uncertainty and retaining a full-suite fallback improves the tradeoff.

Methods implemented: Parse source with ast; construct module import dependencies;
traverse reverse dependencies; select connected test modules. Dynamic execution,
parse failures, unknown changes and empty selections trigger full-suite fallback.
Record hashes, selected paths, reasons and actual subprocess outputs.

Experiments implemented: Four original synthetic dependency patterns, each with a
clean implementation and a deliberately wrong arithmetic mutation. Run clean suite,
then full suite, fixed-prefix budget control and ImportGuard on the mutation. Raw
outputs are stored in results/smoke-benchmark.json after execution. These are diagnostic
fixtures, not evidence of generalization or new state of the art.

Next experiment: Freeze a manifest of public, permissively licensed Python bug/fix
pairs and document each license. Split by repository before tuning. Compare full,
random equal-budget (multiple seeds), coverage selection, static imports without
fallback and with fallback. Never expose held-out test outcomes to the selector.
Run an actual local Gemma agent with the same tasks and inference budget in each arm.
Use existing baseline implementations only after checking licenses. Report all failures,
empty selections and timeouts, and measure false-negative fault detection explicitly.
